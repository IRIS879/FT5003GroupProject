# Forum Builder Fund DAO (论坛建设基金 DAO) MVP 治理规则 - Lite Version

## 一、治理目标
- Forum Builder Fund DAO 是面向高质量内容社区或开发者论坛的社区建设基金治理机制。
- 论坛按固定周期设立一笔公共预算，资金统一存放于 DAO Treasury 智能合约中。
- 治理目标：由真实贡献者共同决定有限社区资金的分配方式，并由智能合约自动执行拨款。
- 资助范围：开发论坛工具、撰写高质量内容、组织社区活动等。

## 二、成员资格与白名单信誉制
- 仅白名单成员有资格提交提案和参与投票。
- 白名单由版主团队或核心委员会管理，采用多签机制进行维护。
- **纯信誉制（无押金）**：MVP 阶段基于严格的白名单准入机制来防范女巫攻击（Sybil Attack）。若白名单成员提交恶意或虚假提案，将在形式审查环节被直接拦截，并面临被移出白名单的惩罚，因此无需引入复杂的资金押金机制。

## 三、Funding Round 制度
- DAO 采用固定周期的 funding round 机制进行治理，例如每 **30 天** 为一轮。
- 每轮治理流程如下：
  - 提案提交期：**7 天**
  - 形式审查期：**3 天**
  - 投票期：**5 天**
  - 自动执行期：投票结束后系统立即结算拨款。
- 每轮设定固定预算（如 **5,000 USDC**）。单个提案申请金额不得超过本轮预算的 **20%**。

## 四、提案提交与审查规则
- 每位白名单成员每轮最多提交 **1 项提案**。
- 提案必须包含：标题、资金用途、申请金额、收款地址、项目说明与预期价值。
- **形式审查**：管理团队仅检查提案信息是否完整、金额是否合规、内容是否恶意。通过形式审查的提案即可直接进入投票阶段。

## 五、投票机制 (Approval Voting)
- 仅白名单成员可进行有效投票，提案人不得对自己的提案投票。
- 采用 **赞成票机制 (Approval Voting)**：每位投票人可对本轮中任意多个认可的提案投出“赞成票”（每人对单一提案最多计 1 票，不设权重）。
- 为降低拉票风险，投票期间不实时公开个人投票内容，仅在投票结束后统一公布汇总结果（Delayed Reveal）。

## 六、法定参与与通过门槛 (Fixed Quorum & Threshold)
- **固定法定门槛 (Quorum)**：为简化系统运算，MVP 阶段采用绝对数值门槛。每轮投票总参与人数必须达到 **5 人**（可根据社区规模硬编码调整），当轮治理结果方为有效。
- **通过门槛**：单个提案至少需要获得 **3 张赞成票**，方可进入后续的排序候选名单。

## 七、排序与预算分配规则
- 所有达到通过门槛的提案，按照 **获得的总赞成票数** 从高到低统一排序。
- 若出现平票，则直接按照 **提案提交时间的先后** 进行排序优先处理。
- 系统按照排序结果依次拨款，直至本轮预算用尽。若某项提案申请金额高于当轮剩余预算，则该提案本轮不执行。

## 八、Treasury 自动执行与透明度
- 所在轮次达到 Quorum、提案过线且在预算范围内时，智能合约自动将资金拨付至收款地址。
- 提案状态包括：`Submitted` (已提交)、`Voting` (投票中)、`Approved` (已通过)、`Rejected` (已拒绝)、`Executed` (已执行)。
- 所有预算规模、最终投票结果、拨款记录对全员公开且链上可查。
